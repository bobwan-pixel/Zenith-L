# Android build, signing, and releases

## Build locally

Requirements: Android Studio (or Android SDK + JDK 17), the Android SDK platform 35, NDK 27.2.12479018, and CMake 3.22.1.

Debug APK:

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Windows:

```powershell
.\\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

Output: `app/build/outputs/apk/debug/app-debug.apk`. Debug builds use the debug signing key generated by Android tooling and have the `.debug` application ID suffix.

## Create the one permanent Release keystore

Create the keystore once. Keep a secure offline backup. Losing it means future updates cannot be installed over builds signed with that key. Create the folder first.

```bash
mkdir -p keystore
keytool -genkeypair -v -keystore keystore/zenith-release.jks -alias zenith-release -keyalg RSA -keysize 4096 -validity 10000
```

On Windows PowerShell, create the folder with `New-Item -ItemType Directory -Force keystore` before running `keytool`.

Copy the tracked template to the ignored local configuration file:

Linux/macOS:

```bash
cp keystore.properties.example keystore.properties
```

Windows PowerShell:

```powershell
Copy-Item keystore.properties.example keystore.properties
```

Edit `keystore.properties` and replace every placeholder. The default `storeFile` path and alias match the keystore command above. This file is ignored by Git.

Do not commit the keystore, passwords, or `keystore.properties`. Keep the same keystore and alias for every future release.

Build the signed Release APK:

```bash
./gradlew assembleRelease
```

Windows:

```powershell
.\\gradlew.bat assembleRelease
```

Output: `app/build/outputs/apk/release/app-release.apk`. A Release build deliberately fails if signing is not configured or the keystore file is missing.

Local version defaults are in `version.properties`. Override them for a one-off build with `-PVERSION_CODE=5 -PVERSION_NAME=0.4.1`. Android requires each published versionCode to be greater than the previous published versionCode.

## Configure GitHub Actions signing

Use the exact same JKS file created above. Base64-encode it without changing the file:

Linux:

```bash
base64 -w 0 keystore/zenith-release.jks
```

macOS alternative:

```bash
base64 < keystore/zenith-release.jks | tr -d '\\n'
```

Windows PowerShell:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("keystore/zenith-release.jks"))
```

In GitHub repository **Settings → Secrets and variables → Actions**, add these repository secrets:

- `RELEASE_KEYSTORE_BASE64`: the complete Base64 output of the JKS file.
- `RELEASE_STORE_PASSWORD`: keystore password.
- `RELEASE_KEY_ALIAS`: `zenith-release` (or the alias you chose).
- `RELEASE_KEY_PASSWORD`: key password.

Never paste these values into source code, commits, issues, or chat. The workflow writes the decoded keystore only to the runner's temporary directory and does not upload it as an artifact.

## Cloud builds

- Pull requests: run tests, lint, and build a Debug APK artifact.
- Push to `main`: build and upload Debug and signed Release APK artifacts. The Release job requires the four signing secrets above.
- Windows desktop packaging and Android native emulator tests run as separate CI jobs.
- Push a version tag such as `v0.4.1` to build a signed APK and publish a GitHub Release with generated release notes.

Example:

```bash
git tag v0.4.1
git push origin v0.4.1
```

Both local and cloud Release builds read the same keystore settings. Do not generate a new keystore for CI or for each version. If the signing key is rotated, Android treats it as a different signer and normal in-place updates may fail.
